# The Effect Native guide

A buildable tutorial for building an app on Effect Native, written against
what's actually shipped in this repository — not what's planned.

## Who this is for

You don't need to know Effect already, but you should be comfortable reading
TypeScript. If you've used React or React Native, most of the friction in
this guide is unlearning specific habits (components as functions, state as
hooks, event handlers as closures) — page 3 has a translation table for
exactly that.

## Status

**Pre-alpha.** APIs shown here will change without notice until a first
tagged release. The catalog is intentionally closed (see
[`../../GAPS.md`](../../GAPS.md)) — you can't invent a new component the way
you'd write a new React component. That's a constraint the rest of the guide
explains and justifies, not a temporary limitation.

Every `ts`/`typescript` code block in this guide is extracted and
type-checked against the real workspace packages by
[`scripts/check-doc-snippets.ts`](../../scripts/check-doc-snippets.ts), wired
into `bun run check:doc-snippets` (and into `bun run check`). If a snippet
here doesn't compile, that's a bug — file it.

## Reading order

1. [**Install and setup**](./01-install-and-setup.md) — get a workspace
   talking to `@effect-native/core`.
2. [**Views are data**](./02-views-as-data.md) — the closed v0 catalog:
   `Stack`, `Text`, `Button`, `Image`, `TextField`, `List`, `Card`, `Spacer`.
3. [**The intent algebra**](./03-intents.md) — why interactions are typed
   values dispatched by name, never closures embedded in a view.
4. [**The runtime**](./04-runtime.md) — binding a view function to live
   state and an intent registry to get one runnable program.
5. [**The DOM renderer**](./05-dom-renderer.md) — mounting that program in a
   browser with no React involved.
6. [**The React Native renderer**](./06-react-native-renderer.md) — the same
   program, unmodified, on iOS/Android via Expo.
7. [**Catalog reference**](./07-catalog-reference.md) — every shipped
   component's typed props, generated by reading the real schemas in
   [`packages/core/src/index.ts`](../../packages/core/src/index.ts).

## The worked example this guide builds

Pages 2 through 6 build one small app together: **Notes** — a text field, an
"add" button, and a list of cards. It's small on purpose; it's built once and
carried through renderer, intent, and runtime chapters so you can see the
same pieces do different jobs in each one.

For a larger, more realistic worked example — a signup form with
field-level validation, a live activity feed, and a cross-renderer behavioral
oracle — read [`../proof.md`](../proof.md) after finishing this guide. That
example is what `bun run example:web` and the mobile app under
`examples/mobile` actually run.

## Non-goals of this guide

- It does not cover navigation, styling variants, forms, overlays, or
  virtualized lists in depth. Those exist in the catalog today (see
  [`../../GAPS.md`](../../GAPS.md) for what shipped and when) but this guide
  stops at the fundamentals: views as data, intents, the runtime, and the two
  shipping renderers. Read the catalog reference and the source in
  `packages/core/src/index.ts` for the rest.
- It does not stand up a docs website. This is plain Markdown, read in the
  repository or on GitHub.
